# MTG Proxy Creator — Review Findings

Review of `mtg_test_cards.py` (read-only; nothing was altered). Items are grouped
by severity. "Verified" means the behaviour was reproduced against the live
Scryfall bulk DB (~38,700 cards) during this review.

## 1. Bugs / functional defects

| # | Item | Detail |
|---|------|--------|
| 1.1 | **Text-box overflow is not bounded** — **fixed** | `draw_text_block()` now caps the block at the lines that fit between the type rule and `Z_TEXT_BOT` and cuts the last kept line with an ellipsis. Re-verified on the worst DB card (*Baldur's Gate Wilderness*, 1489 ch): 0 text blocks fall below the box rule (lowest text y 267.3 vs rule at 271.3 in PDF space) and it is now reported as `('rules text cut off', …)` instead of silently clipped. |
| 1.2 | **Silent name shadowing from normalization** — **fixed** | `resolve()` prefers an exact case-insensitive name over the normalized key and emits a "matches several cards; used … Also found: …" note when only the normalized form matches. Probe against the live DB (38,766 keys): `Goblin Soldier` → the token card of that exact name (not *Goblin // Soldier*), and `Clear the Mind` / `Clear, the Mind` each resolve to their own card - 0 problems raised. |
| 1.3 | **Cards whose names normalize to empty are unprintable** — **fixed** | `load_database()` keys such entries by `_norm(name) or name.casefold()`, and `resolve()` falls back to that raw key, so the Scryfall cards literally named `_____` and `______` resolve when typed exactly (probe: both resolved, layout `normal`). |
| 1.4 | **`MIN_TEXT` floor is violated by design** — **fixed** | `fit_name_cost()`'s last resort rendered names at 3 pt (below the documented 6 pt floor) and `truncate_to_fit()` tested only the shortened candidate, so one glyph of overshoot collapsed whole names to a bare ellipsis. The shrink loop now stops at `MIN_TEXT` and shortening happens there; 340 DB names take this path and all print at 6 pt with a readable prefix (verified against the live DB: 0 names below the floor). Documented in SPEC.md §6.1. |
| 1.5 | **Unbreakable over-long tokens** — **fixed** | `wrap_text()` gained `split_overlong()`, which hard-splits a token wider than `max_width` character by character, so no line ever exceeds the box (probe: a 72-char token at both `TEXT_SIZE` and `MIN_TEXT` yields widest line 150.4–150.7 pt inside the 153.6 pt limit). The justification pass it used to feed no longer exists - lines are drawn left-aligned - so the negative word-gap overlap cannot occur. |
| 1.6 | **Empty / bad output path fails with a raw exception** — **fixed** | `_generate_worker()` validates before rendering: blank field, existing directory, and non-existent parent folder each raise their own sentence ("pick a valid output path", "is a folder - pick a file name inside it") and the `.pdf` extension is appended case-insensitively; reportlab is never reached with an unusable path. |
| 1.7 | **No lock around DB parsing** — **fixed** | `_parse_lock` now serializes the ~25 MB parse: both `_preload_db()` and `_generate_worker()` take it, each re-checking `self.db is None` inside the lock, so the DB is parsed at most once per run whichever thread arrives first. |
| 1.8 | **Silent overwrite of the default PDF** — **fixed (notice)** | The completion dialog now adds "Note: this replaced an existing file at …" when the target already existed (`existed = os.path.isfile(out_path)` before rendering). A timestamped filename or a real confirmation prompt remains a §2 feature request, not a defect. |
| 1.9 | **Art (art-series) printings hijacked name matching** — **fixed** | The Oracle bulk carries 2,411 art prints (`layout == 'art_series'`, in 45 sets named "… Art Series"), each named `X // X` with no cost, type line or rules text. They duplicate real card names and are loaded first, so a bare name resolved to the art print and printed an empty card: before the fix `Kobold` → `Minion of the Mighty // Kobold`, `Hobgoblin` → `Hobgoblin Bandit Lord // Hobgoblin`, `Tarrasque` → `The Tarrasque // Tarrasque`, `Basilisk` → `Underdark Basilisk // Basilisk`, and typing a DFC back (`Ashen Reaper`, `Witch-Blessed Meadow`) reached the art twin by DB luck. Fix: `load_database()` flags `art_card`, `_real_cards()` filters main-index hits, `_face_index()` skips art records and `_name_index()` drops art-only keys (so "Did you mean" never offers `X // X`). An art print stays reachable only through an exact full typing, which is why the harness line `Hobgoblin Bandit Lord // Hobgoblin` still resolves and `layout_check.py` still prints 42 faces / 5 pages. Post-fix probe: `Ashen Reaper` → *Invasion of Azgol*, `Ambitious Farmhand` → *Ambitious Farmhand // Seasoned Cathar*, while the 26 names that exist only in art series (`Tarrasque`, `Kobold`, `Ettin`, `Troll`, …) now report "no card with this name was found" with near-match suggestions instead of printing blank cards. |

## 2. Missing features (candidates)

- **No direct print path** — **half closed**: the completion dialog now ends with "Print at 100% scale for the real 63.00 x 88.00 mm card size.", so the reminder half of the request is done; an actual Print action (spooling to a printer) remains open.
- **No ambiguity assistance** — for item 1.2: show near-matches / all cards sharing the normalized key when resolution is not exact on the raw name.
- **Per-card quality warnings are invisible** — **fixed**: `build_pdf()` now returns `(reason, name)` pairs collected from every frame type (standard box, split/flip halves via `draw_mini_face`, Adventure inset via `_draw_inset_panel`, stacked panels) and the completion dialog lists them grouped by reason - "rules text cut off" and "name shortened". The inset panel had been silently uncappable before this: *Meager Meal* (145-char Adventure text in a 34 x 18 mm box) is now named as cut off.
- **No settings persistence** — paper size and output path reset to defaults on every launch.
- **No list import/export** — drag-and-drop of a `.txt` deck file, or saving the entered list; only manual typing/pasting into the text box.
- **No sanity cap on quantity** — **fixed as a note, not a cap**: any `qty >= 1` stays legal, but a per-line quantity over `QTY_NOTE_ABOVE = 20` adds "Large quantities requested (expect many pages): line N: xQ copies" to the completion dialog. Probe: `30x Sol Ring` + `2x Lightning Bolt` → 32 faces on 4 pages at 9/page, with the x30 line named.
- **Mana colors are flattened by design** (`{1}{U}` → `1U`, `{W}/{U}` → `W/U`) — fine for B/W printing, but a legend or colored-cost annotation option would help identify mana requirements at the table.
- **Flip / double-faced backs and their stat values** — **verified**: every `card_faces` entry carries its own `power`, `toughness`, `loyalty` and `defense` (live DB: 910 faces with power, 23 with loyalty, 37 with defense), and `_base_item()` copies all four from the *face* record, so a flip half prints its own stat line via `draw_mini_face`: *Nezumi Graverobber* 2/1 → *Nighteyes the Desecrator* 4/2, *Curse of the Fire Penguin* (none) → *Curse of the Fire Penguin Creature* 6/5, essence sides (*Sasaya's Essence*, *Rune-Tail's Essence*) and role tokens (*Wicked*, *Royal*) correctly print none, and the back of a double-faced planeswalker prints its starting loyalty counter (*Ral, Leyline Prodigy* 2, *Grist, the Plague Swarm* 3, *Liliana's Undead Minion* 5) while battle fronts print defense (*Invasion of Azgol* 4). Added for playtesting: `FRONT` / `BACK` tags bottom-left in each half of a flip card (a split card's two spells share one face, so it stays untagged), and the half stat baseline is clamped to `max(y + MINI_TEXT_BOT * MM, y + 3.0 * MM * k)`. Verified on the rendered PDF: word boxes for `2/1` (x 178.5–188.4) vs `FRONT` (x 48.7–69.4) and `4/2` vs `BACK` sit inside their half with no overlap.
- **No deck metadata in the PDF** (deck name, date) beyond the fixed title "MTG Test-Play Cards".

## 3. Edge cases to confirm / document (mostly OK as-is)

- Quantity formats accepted: `2x name`, `2 x name`, `2 * name`, `2 × name`, bare name = 1, bullet/`-` prefixes stripped. **Not** accepted: `2xname` (no space after the letter) — it is treated as a card name and fails to resolve. Document the grammar.
- `0x name` → friendly "quantity must be at least 1" error (handled).
- Case-insensitive matching, diacritic-stripped matching (`Ætherling` ↔ `aetherling`) — both sides normalize identically, verified working.
- Star P/T (`*/*`, `*/5`) and loyalty fallback render correctly (verified); cards with **both** P/T and loyalty show P/T only — document as intended precedence.
- Zero-cost `{0}` → `0`; `X` costs pass through unchanged — fine.
- Very small paper: `compute_grid` raises a clear RuntimeError for paper that can't fit one card — OK, but the GUI surfaces it as a generic failure dialog; acceptable.
- Offline operation: a local `oracle-cards*.jsonl.gz` next to the script is reused without network (verified) — good; keep this behaviour documented.
